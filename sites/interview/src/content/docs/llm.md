# LLM 面试题

## Transformer 架构

### Q1: 为什么 Transformer 用 Scaled Dot-Product 而不是 Dot-Product？

当向量维度 $d_k$ 较大时，点积的值会很大，导致 softmax 梯度极小（进入饱和区），训练困难。除以 $\sqrt{d_k}$ 可以将方差稳定在 1 左右，让 softmax 保持在梯度较大的区域。

### Q2: Multi-Head Attention 的作用是什么？

多个注意力头可以关注不同的子空间信息。比如一个头关注语法关系，一个头关注语义关系，一个头关注位置关系。每个头的维度是 $d_k = d_{model} / h$，总计算量与单头注意力相同。

### Q3: 为什么 Transformer 需要位置编码？

Self-Attention 是置换不变的——打乱输入顺序，输出不变。但语言是有顺序的（"我吃了苹果"和"苹果吃了我"意思不同），所以需要位置编码注入位置信息。

### Q4: Decoder-only 和 Encoder-only 的区别？

- **Encoder-only**（如 BERT）：双向注意力，适合理解任务（分类、NER）
- **Decoder-only**（如 GPT）：因果注意力（只看左边），适合生成任务
- **Encoder-Decoder**（如 T5）：适合序列到序列任务（翻译、摘要）

现在主流 LLM 都是 Decoder-only，因为生成任务最通用，且 Scaling Law 效果最好。

## 训练与优化

### Q5: 什么是 Teacher Forcing？

训练时将真实标签作为下一步输入，而不是模型自己的预测。优点是训练稳定、收敛快；缺点是训练和推理有差异（exposure bias），推理时错误会累积。

### Q6: Top-k、Top-p 采样怎么选？

- **Top-k**：从概率最高的 k 个 token 中采样。简单但不自适应——有时 k 个候选太多，有时太少。
- **Top-p**（Nucleus Sampling）：从累积概率达到 p 的最小 token 集合中采样。更自适应，是目前主流选择。
- **Temperature**：控制分布的尖锐程度。T→0 变成 Greedy，T→∞ 变成均匀分布。

推荐：Top-p=0.9、Temperature=0.7 是不错的起点。

### Q7: 什么是 KV Cache？

生成时每个 token 需要与之前所有 token 做注意力。KV Cache 缓存已计算的 Key 和 Value，避免重复计算。这将生成复杂度从 $O(n^2)$ 降到 $O(n)$（每步），是推理加速的关键技术。

### Q8: 什么是 Perplexity？

Perplexity（困惑度）是语言模型的核心评估指标：

$$
PPL = \exp\left(-\frac{1}{N}\sum_{i=1}^{N} \log P(w_i | w_{<i})\right)
$$

直觉上，PPL=10 意味着模型在每个位置平均有 10 个等概率的候选。PPL 越低，模型越好。

## Fine-tuning

### Q9: LoRA 的核心思想是什么？

微调时权重更新矩阵 $\Delta W$ 是低秩的，可以分解为两个小矩阵 $B$ 和 $A$ 的乘积。冻结原始权重，只训练 $B$ 和 $A$，可训练参数量从 $d^2$ 降到 $2dr$。

### Q10: RAG 和微调怎么选？

- **RAG**：知识频繁更新、需要引用来源、数据量少
- **微调**：改变模型风格、提升特定能力、数据量充足
- **结合**：先微调适配风格，再用 RAG 注入最新知识

### Q11: 如何避免灾难性遗忘？

(1) 小学习率；(2) 混入通用数据；(3) 使用 LoRA 等参数高效方法；(4) 定期评估通用能力。

## 工程实践

### Q12: LLM 推理怎么优化？

| 方法 | 原理 | 效果 |
|------|------|------|
| KV Cache | 缓存已计算的 K/V | 避免重复计算 |
| 量化 | FP16→INT8/INT4 | 显存减半，速度提升 |
| 批处理 | 多个请求一起推理 | 提升吞吐 |
| Flash Attention | 优化注意力计算 | 减少显存，加速 |
| 推测解码 | 小模型预测+大模型验证 | 加速 2-3 倍 |

### Q13: 怎么评估 LLM 的效果？

分层评估：
1. **基础能力**：MMLU、HumanEval、GSM8K 等基准
2. **任务效果**：具体任务的指标（准确率/F1/BLEU）
3. **人工评估**：答案质量、安全性、有用性
4. **线上指标**：用户满意度、留存率

### Q14: LLM 的幻觉怎么缓解？

(1) RAG 引入外部知识；(2) 要求模型引用来源；(3) 使用低温度减少随机性；(4) 后处理校验（事实核查）；(5) 微调时使用高质量数据。

## 系统设计

### Q15: 设计一个 LLM 应用需要考虑什么？

1. **模型选择**：效果 vs 成本 vs 延迟
2. **Prompt 工程**：系统提示、Few-shot 示例
3. **上下文管理**：对话历史长度、摘要压缩
4. **安全防护**：输入过滤、输出检查、敏感词
5. **可观测性**：日志、监控、告警
6. **成本控制**：缓存、限流、模型降级

### Q16: 怎么控制 LLM 的输出格式？

(1) Prompt 中给出明确的格式要求和示例；(2) 使用 JSON Mode（部分 API 支持）；(3) 使用结构化输出库（如 Instructor）；(4) 后处理解析和校验；(5) 微调时使用格式化的训练数据。

## 高频追问

**Q: 为什么现在都用 Decoder-only 而不是 Encoder-Decoder？**

三个原因：(1) Scaling Law 表明 Decoder-only 在大规模下效果更好；(2) 生成任务最通用，理解任务可以通过生成来实现；(3) 架构更简单，训练和推理优化更容易。

**Q: 什么是 RLHF？和 DPO 有什么区别？**

RLHF 用人类偏好训练一个奖励模型，再用 PPO 优化策略模型使其最大化奖励。DPO 直接从偏好数据中学习，不需要训练奖励模型，更简单稳定。DPO 的核心是将 RL 问题转化为分类问题。

**Q: 7B 模型和 70B 模型的本质区别是什么？**

主要是容量（参数量决定了模型能记住多少知识和多复杂的模式）。70B 模型在推理能力、知识覆盖、少样本学习上都显著优于 7B。但 7B 模型推理成本低 10 倍，适合对成本敏感的场景。
